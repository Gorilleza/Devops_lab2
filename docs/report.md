## Ответы на контрольные вопросы

**1. Что такое обмен сообщениями (messaging) и какие проблемы в архитектуре ПО он решает?**
Обмен сообщениями — это способ связи между компонентами системы через асинхронную передачу данных (сообщений). Это решает проблемы сильной связанности (когда сервисы зависят друг от друга), позволяет сглаживать пиковые нагрузки, обеспечивает отказоустойчивость (сообщения не теряются, если получатель временно недоступен) и масштабируемость.

**2. Что такое брокер сообщений? Какова его роль в системе?**
Брокер сообщений — это промежуточное ПО (сервер), которое принимает сообщения от отправителей (продюсеров), маршрутизирует их и доставляет получателям (консьюмерам). Он выступает посредником, позволяя приложениям общаться, не зная друг о друге напрямую.

**3. Перечислите и охарактеризуйте основные шаблоны (паттерны) обмена сообщениями.**
- **Point-to-Point (Очередь):** сообщение получает только один потребитель.
- **Publish/Subscribe (Публикация/Подписка):** сообщение получают все подписчики (рассылка).
- **Request/Reply (Запрос/Ответ):** отправитель ждет ответа от получателя (RPC).

**4. Дайте определение RabbitMQ.**
RabbitMQ — это популярный брокер сообщений с открытым исходным кодом, написанный на языке Erlang. Он реализует протокол AMQP и поддерживает множество сценариев маршрутизации.

**5. Какой протоколом лежит в основе RabbitMQ?**
Основной протокол — **AMQP 0-9-1** (Advanced Message Queuing Protocol). Также поддерживаются MQTT, STOMP.

**6. В RabbitMQ сообщения, принятые от приложения-продюсера (издателя), записываются ...**
...в **точки обмена (Exchanges)**. Продюсер никогда не отправляет сообщения напрямую в очередь, только в обменник.

**7. Объясните, что такое точка обмена (exchange).**
Exchange — это сущность, которая принимает сообщения от продюсеров и решает, в какие очереди их направить, основываясь на правилах (bindings) и ключах маршрутизации (routing key).

**8. Что такое Binding в RabbitMQ?**
Binding — это связь (правило) между точкой обмена (exchange) и очередью (queue). Она определяет, какие сообщения из обменника попадут в эту очередь.

**9. Дайте определение Routing Key в Rabbit MQ.**
Routing Key — это строковый атрибут сообщения, который продюсер указывает при отправке. Обменник использует его для сопоставления с правилами Binding, чтобы решить, в какую очередь отправить сообщение.

**10. Опишите по шагам процесс маршрутизации сообщения в RabbitMQ (от продюсера до потребителя).**
1. Продюсер публикует сообщение в Exchange с указанием Routing Key.
2. Exchange проверяет свои Bindings и сопоставляет Routing Key.
3. Сообщение копируется в одну или несколько очередей (или отбрасывается, если связей нет).
4. Потребитель (Consumer), подписанный на эту очередь, получает сообщение.
5. Потребитель отправляет подтверждение (ACK) после обработки.

**11. Если необходимо просто распараллелить обработку сообщений, принятых от продюсера (издателя) по нескольким потребителям, какой тип обменника надо выбрать в RabbitMQ?**
Нужно использовать **Fanout Exchange** (он рассылает сообщения во все привязанные очереди) или **Direct Exchange** (с несколькими очередями, привязанными по одному Routing Key). Для балансировки нагрузки между потребителями лучше всего подходит прямая очередь (Direct) с несколькими воркерами.

**12. Какие типы точек обмена (exchanges) существуют в RabbitMQ и в чем их принципиальные отличия?**
- **Direct:** маршрутизация по точному совпадению Routing Key.
- **Fanout:** игнорирует Routing Key, рассылает во все привязанные очереди.
- **Topic:** маршрутизация по шаблону (маске) в Routing Key (символы `*` и `#`).
- **Headers:** маршрутизация по заголовкам сообщения, а не по ключу.

**13. Обычно приложение-продюсер отправляя сообщение в RabbitMQ, отправляет его ......**
...в **точку обмена (Exchange)** с указанием Routing Key.

**14. Как предотвратить потребление устаревших данных из RabbitMQ?**
Использовать TTL (Time-To-Live) для сообщений или очередей (сообщения удаляются по истечении времени). Также можно использовать Dead Letter Exchange (DLX) для перенаправления просроченных сообщений.

**15. По какому принципу LIFO или FIFO устроены очереди в RabbitMQ, в которые записываются сообщения?**
Очереди в RabbitMQ работают по принципу **FIFO** (First In, First Out) — первое пришедшее сообщение будет первым доставлено потребителю (если не настроены приоритеты).

**16. Для чего предназначен Server (Broker/Node) в RabbitMQ.**
Сервер (узел) — это сам процесс RabbitMQ, который хранит очереди и обменники, управляет подключениями и маршрутизирует сообщения.

**17. Опишите назначение Virtual Host (Vhost) в RabbitMQ.**
Virtual Host — это логическая изоляция внутри брокера. У каждого Vhost свои очереди, обменники и права доступа пользователей. Позволяет использовать один сервер RabbitMQ для разных независимых приложений.

**18. Что такое подтверждение сообщений (acknowledgments /ack, nack, reject) и зачем оно необходимо?**
Это механизм, при котором потребитель сообщает брокеру, что успешно обработал сообщение (`ack`). Если потребитель упал до `ack`, сообщение не удаляется из очереди и будет доставлено другому потребителю. `nack` (отказ) и `reject` (отклонение) используются для возврата или удаления сообщения.

**19. Чем отличаются долговечные (durable) и временные (transient) очереди и сообщения? Как это влияет на перезагрузку брокера?**
`durable` (долговечные) очереди и сообщения сохраняются на диск и переживают перезагрузку брокера. Временные (`transient`) удаляются при перезапуске.

**20. Что такое Dead Letter Exchange (DLX) и какие сценарии его использования?**
DLX — это «обменник мертвых писем». В него перенаправляются сообщения, которые не удалось обработать (отклоненные, просроченные или превысившие лимит очереди). Используется для логирования ошибок или повторной обработки.

**21. Что такое Priority Queue в RabbitMQ и как она работает?**
Это очередь, в которой сообщения имеют приоритет (целое число). Сообщения с более высоким приоритетом доставляются раньше, даже если пришли позже. Настраивается при объявлении очереди.

**22. Дайте определение Apache Kafka. Какие основные задачи она решает и чем ее философия отличается от классических брокеров?**
Kafka — это распределенная платформа для потоковой передачи данных (стриминга). Она работает как распределенный журнал (log). В отличие от классических брокеров, Kafka не удаляет сообщения сразу после прочтения (они хранятся заданное время), и потребители сами отслеживают свой прогресс (offset), а не брокер.

**23. Опишите архитектуру Kafka. Что такое Broker, Topic и Partition?**
- **Broker:** сервер в кластере Kafka, хранящий данные.
- **Topic:** логический канал (тема) для сообщений.
- **Partition:** физическая часть топика (неизменяемый лог), обеспечивающая параллелизм и масштабирование.

**24. Что такое Consumer Group (группа потребителей) и как она влияет на масштабирование и распараллеливание чтения?**
Consumer Group — это группа потребителей, которые совместно читают сообщения из топика. Каждый раздел (partition) читается только одним потребителем из группы, что позволяет распараллелить чтение и масштабировать обработку.

**25. Что такое реплика (Replica)? Чем роль Leader отличается от роли Follower?**
Реплика — это копия раздела (partition) на другом брокере для отказоустойчивости. **Leader** принимает все запросы на чтение/запись, а **Follower** реплицирует данные у себя, готовый стать лидером при его падении.

**26. Что такое ZooKeeper (или подсистема Kraft в новых версиях) и какова его роль в архитектуре Kafka?**
Это координатор кластера. В старых версиях ZooKeeper хранил метаданные кластера и управлял лидерами. В новых версиях используется **KRaft** (Kafka Raft), встроенный протокол консенсуса, позволяющий отказаться от ZooKeeper.

**27. Что такое Kafka Streams и как он отличается от написания Consumer-приложений?**
Kafka Streams — это библиотека для обработки потоков данных. Она абстрагирует сложность работы с потребителями и предоставляет высокоуровневые операции (фильтрация, агрегация, соединения). Вместо ручного цикла чтения вы описываете топологию обработки.

**28. В чем заключаются фундаментальные архитектурные отличия между RabbitMQ и Apache Kafka (модель хранения, маршрутизация, состояние сообщений)?**
- **Хранение:** RabbitMQ — очередь (удалил после прочтения), Kafka — распределенный лог (хранит сообщения долго).
- **Маршрутизация:** RabbitMQ — умный брокер (exchange/bindings), Kafka — тупой брокер (топики/партиции, потребитель сам читает).
- **Состояние:** RabbitMQ управляет состоянием очереди, Kafka позволяет потребителям управлять своими offset'ами.

**29. Приведи примеры, в каких сценариях предпочтительнее использовать RabbitMQ, а в каких — Apache Kafka.**
- **RabbitMQ:** сложная маршрутизация, очереди задач, RPC, микросервисы с низкой задержкой, требующие подтверждений.
- **Kafka:** большие потоки данных (Big Data), логирование, аналитика в реальном времени, Event Sourcing, потоковая обработка, где нужна высокая пропускная способность.

**30. Можно ли использовать RabbitMQ и Apache Kafka в одной архитектуры? Если — да, то за какие зоны ответственности каждый из них будет отвечать?**
Да, можно. Пример: **Kafka** используется для сбора и хранения сырых событий (логов, телеметрии) и их потоковой обработки, а **RabbitMQ** — для доставки команд между микросервисами (например, отправка уведомлений или распределение задач на воркеры).
